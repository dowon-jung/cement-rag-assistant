### 3. 폴더 구조 3단계 재편성

**변천 과정:**

```
1단계 — 초기 모놀리식
  src/app/ 하위에 모든 코드 통합

2단계 — docs/src/infra 3분리
  MD 문서 → docs/
  Python 코드 → src/
  인프라 설정 → infra/

3단계 — MSA 구조 확정 (최종)
  src/services/collector/   수집 서비스
  src/services/indexer/     인덱싱 서비스
  src/services/agent/       Agent 서비스
  src/services/gateway/     API 게이트웨이
  src/services/evaluator/   평가 서비스
  src/shared/               공통 코드
```

**MSA 선택 이유:**
공공 API 교체, RAG 엔진 교체, LLM 백엔드 변경이 각각 독립적으로 가능하도록. 서비스 간 Kafka 토픽으로만 통신하면 한 서비스를 바꿔도 다른 서비스에 영향이 없다.

**생성 문서:** `docs/design/00_folder_structure.md` — 구조 의도 및 변천 과정 기록

## 주요 의사결정 기록

**Q. WSL2 vs VMware vs Windows 로컬 중 어떤 환경으로 개발하는가?**
Windows 로컬에서 직접 개발하기로 결정. Docker Desktop이 Windows에서 동작하므로 별도 VM 불필요. Legion Pro 5 (32GB RAM, RTX 5060)로 전체 서비스 운영 가능.

**Q. RTX 5060 활용 계획?**
Phase 9 vLLM 벤치마크를 외부 GPU 서버(RunPod 등) 없이 로컬에서 직접 실행 가능. Gemma2:9b 기준 ~60~80 tok/s 예상.

**Q. MSA에서 서비스 간 통신 규칙은?**
서비스끼리 직접 임포트 금지. 반드시 Kafka 토픽 또는 DB를 통해서만 통신. 이 규칙을 지키면 나중에 공공 API나 RAG 엔진을 교체해도 다른 서비스 코드를 건드리지 않아도 된다.
