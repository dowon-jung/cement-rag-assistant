### 9. 주요 의사결정 기록

**Q. Elasticsearch를 추가한 이유?**
Qdrant의 Sparse Vector는 한국어 형태소 분석이 없어 "시멘트배출기준" 같은 붙여쓴 검색에 취약하다.
Elasticsearch nori 플러그인이 형태소 단위로 분리해 검색 품질을 크게 향상시킨다.
상용 솔루션에서도 대부분 Elasticsearch를 사용한다.

**Q. 왜 LLM을 Anthropic API가 아닌 로컬로 서빙하는가?**
시멘트·철강 제조업 고객사는 보안 정책상 사내 데이터가 외부 서버로 전송되는 것을 허용하지 않는다.
로컬 LLM + AIRGAP_MODE로 데이터가 내부에서만 처리되도록 설계했다.
보안 요건에 따라 Ollama(CPU) → vLLM(GPU) → Bedrock → Anthropic API 순으로 선택 가능하게 추상화.

**Q. Kafka를 도입한 이유?**
PDF 인덱싱, LLM 요약 같은 무거운 작업을 API 요청 스레드와 분리해야 타임아웃이 발생하지 않는다.
Consumer 수를 늘려 처리량을 수평 확장할 수 있고, DLQ로 실패 메시지를 안전하게 재처리할 수 있다.
